# [UI4-01] Shared native theme, floating navigation, branding and motion foundation

## Goal
Establish one reusable native presentation system matching the approved neutral reference so all existing screens can adopt it without changing their business behavior.

## Scope and implementation notes
- Update existing `mobile/src/constants/theme.ts`, `components/app-shell.tsx`, `components/bento-kit.tsx`, `components/motion.tsx`, `app/_layout.tsx`, `app/(tabs)/_layout.tsx` and `app/dev/components.tsx` as needed. Inspect all consumers before changing shared APIs; preserve the kit rather than creating a second one.
- Add semantic light/dark token resolution and minimal persisted UI-only preference state for Light/Dark/System and motion on/off. The Settings child supplies the visible controls. Reuse the current storage pattern, handle missing/invalid values safely, and support OS theme changes without a restart.
- Implement inset rounded tab dock with clear gaps and safe-area-aware content padding, animated active selection, 48 dp targets and correct selected semantics. Preserve existing four routes, labels, back behavior and navigation history. A tab press never sends a feeder command.
- Standardize buttons, inputs, grouped rows, cards, chips, status labels, errors/notices, skeletons, sheets, segmented controls and form footers in both themes; native form interaction and error retention must survive.
- Shared motion must support entrances/presses/sheets, safe numeric presentation, cancellation on scope changes and reduced motion/background behavior. Keep semantic values separate from animation frames. Use installed Reanimated/SVG/Gesture Handler where needed; preserve existing simple/native helpers where sufficient.
- Bundle exact mascot and v2 app icon from the parent attachment under current app assets. Use app icon in header/Settings, mascot in appropriate larger placements; preserve aspect ratios. Update Expo app/Android icon and existing splash/favicon assets/config only as visual branding requires. Verify adaptive-icon masks/padding. Preserve package, permissions, project IDs, scheme and notification settings.
- Commit the durable reference into an appropriate `docs/design/` location and reconcile `DESIGN.md` visual and motion requirements only; preserve behavioral rules. Link the parent issue and exact revision.
- Current dirty `motion.tsx` / package files are an ownership gate, not permission to overwrite them.

## What done looks like
- [ ] Shared component gallery demonstrates every major primitive in light/dark and disabled/loading/error/selected states using one set of semantic tokens.
- [ ] The native dock visually floats and never obscures existing actions/last rows or OS chrome, including small-phone/large-text layouts.
- [ ] Every existing consumer remains type-correct and routed correctly; theme updates reach all mounted screens and sheets.
- [ ] Local theme/motion settings persist and System follows OS changes. No device config write or new dependency.
- [ ] Reduced motion yields final values/content immediately; animation cancels on device change/unmount; no recurring full-list entrance animation or hidden loops.
- [ ] Supplied branding renders on white/gray and dark surfaces, and Android launcher/splash visual changes are verified in an appropriate development build or explicitly remain an unverified acceptance gate.
- [ ] Updated design reference, visual docs and minimal meaningful preference/motion checks are included; no HTML/WebView implementation.
