## Reporting and notifications

Use a shared local coordination directory outside product commits for prompts, sessions, logs, completion reports, and review findings. Workers must report `READY_FOR_REVIEW` or `BLOCKED`; only the orchestrator records `REVIEW_PASS` or `CHANGES_REQUESTED`.

Every worker writes its completion/blocker report and sends `READY_FOR_REVIEW` or `BLOCKED` plus the report path to the orchestrator's exact Herdr terminal with `hc send <parent-terminal> "<status and report path>"`, then stays available for corrections. Pass that parent address explicitly at dispatch; the worker's own `HC_TERMINAL_ID` is not the destination. Cleanup workers likewise send their cleanup/tracker result or blocker. Use `hc send` for corrections, `hc read`/`hc get` for inspection and `hc wait` when waiting for results; do not sleep/poll or infer completion from a process exit. If the parent terminal address is unavailable, resolve it before dispatch rather than starting an unreportable worker. Return fixes to that same worker and worktree. Preserve existing sessions/worktrees on recovery and never start two writers. Messages are notification delivery, not evidence of acceptance; inspect the actual report and commit before advancing.

- Before cleanup, confirm the implementation worker has stopped using the worktree, inspect tracked/untracked changes, and ensure every task commit is preserved by the merged result or retained evidence. Account for squash/rebase merges by comparing the resulting changes rather than relying solely on commit ancestry. If preservation is uncertain, report BLOCKED and retain the worktree.
- Resolve and verify the exact cleanup target is inside `D:/thesis commision/Automated Fish Feeding System/` and is the assigned linked worktree, never the main checkout, another task's folder or a parent directory. For an already missing folder, inspect and remove only its confirmed stale registration; do not broadly prune unrelated worktrees. Leave local/remote branches, PRs, deployments and unrelated worktrees intact.
- Update the assigned Markdown task entry with status, PR link, reviewed commit, merge commit/date, verification evidence, unresolved acceptance gates and cleanup outcome. Mark merged separately from native/hardware acceptance; pending cleanup or acceptance must stay explicit. Serialize tracker writes in a retained checkout so the update survives cleanup, and report the exact diff/commit without automatically committing unrelated work or pushing to `main`.
- The cleanup agent reports the removed path, remaining registration check, tracker change and any blocker. The orchestrator reviews this report and checks newly ready tasks for safe parallel dispatch. A merged PR authorizes this scoped local cleanup and tracker handoff; it does not authorize merging another PR, deployment or hardware operation.
